# سند نیازمندی محصول (PRD) — داشبورد دانش‌آموزی CS50x انزلی

> **کدنام پروژه:** Anzali-CS50-Hub · بازطراحی داشبورد دانش‌آموز
> **نسخه‌ی سند:** ۱.۰ · **تاریخ:** تیر ۱۴۰۵ (July 2026)
> **استک هدف:** Flask + Jinja2 + HTMX + Tailwind (CDN) + SQLite
> **هویت بصری:** دانشگاه هاروارد (Crimson رسمی)

## ۰. چکیده‌ی اجرایی

این سند بازطراحی **داشبورد دانش‌آموزی** پلتفرم آموزشی CS50x بندر انزلی را تعریف می‌کند.
هدف: تبدیل یک «استخوان بک‌اند تمیز اما فرانت‌اند ضعیف» به یک **پنل دانش‌آموزی کامل،
ساده و هدف‌مند** که تمام نیازهای کار کردن و مرور بچه‌های کلاس را برطرف کند و — مهم‌تر از
همه — آن‌ها را به سمت **گرفتن مدرک CS50** هل دهد.

**مسئله‌ی فعلی:** پروژه دو نسخه‌ی موازی دارد. نسخه‌ی Next.js (`src/`) یک ابزار مرور
خوب اما **بسیار شلوغ** است (navbar با ~۱۸ دکمه، داده در localStorage، تک‌کاربره، غیرقابل
دیپلوی). نسخه‌ی Flask (`flask-app/`) بک‌اند تمیز و قابل‌دیپلوی دارد اما فرانت‌اندش ضعیف
است (navbar بی‌هویت، صفحه‌ی اصلی فقط `"Hi sina"`).

**راه‌حل:** Flask را به‌عنوان استک واحد می‌پذیریم، آن را با **تم رسمی هاروارد** می‌پوشانیم،
navbar را ساده‌سازی می‌کنیم، یک داشبورد واقعی می‌سازیم، و بهترین قابلیت‌های ابزار مرور
(فلش‌کارت، تحلیل ضعف، چالش زمان‌دار و...) را به‌صورت **ساده‌تر و سازمان‌یافته‌تر** به آن منتقل
می‌کنیم.

## ۳. معماری اطلاعات و نقشه‌ی ناوبری

### ۳.۱ navbar جدید (به‌جای navbar شلوغ فعلی)

navbar هارواردی با **حداکثر ۵ مورد** — بر اساس اصل «سادگی برای آموزش» پروژه:

```
┌─────────────────────────────────────────────────────────────────────────┐
│ [🛡️ لوگو]  Anzali · CS50x          [داشبورد] [تکالیف] [منابع] [رتبه‌بندی]   [👤 شما] │
└─────────────────────────────────────────────────────────────────────────┘
   ▲ نوار قرمز Crimson زیر navbar
```

| مورد navbar | مقصد | منطق |
|-------------|------|------|
| **داشبورد** | `/` | خانه: خلاصه‌ی پیشرفت مدرک، تکالیف نزدیک، میان‌برها |
| **تکالیف** | `/assignments` | «الان چه تکلیفی داری؟» — تحویل گیت‌هاب |
| **منابع** | `/resources` | دانلود اسلاید/جزوه/سورس هر هفته |
| **رتبه‌بندی** | `/gamification/leaderboard` | لیدربورد کلاس + XP + استریک |
| **شما (avatar)** | dropdown | ورود/خروج، پروفایل، مسیر مدرک، تنظیمات |

> **دکمه‌های شلوغ حذف‌شده از navbar** (فلش‌کارت، تایمر، تحلیل ضعف، چالش زمان‌دار،
> دستاوردها، استریک، نقشه راه، میانبرها، اشتراک نمره) به‌عنوان **بخش‌های منطقی داخل
> صفحات** جای می‌گیرند. این یعنی UX پاک‌تر و هدف‌مندتر.

### ۳.۲ نقشه‌ی صفحات

```
/                              داشبورد اصلی (خلاصه‌ی همه‌چیز + پیشرفت مدرک)
├── /kb/week/<n>               پایگاه دانش هفته (مفاهیم + کد + کوییز + ابزار مطالعه)
├── /assignments               تکالیف فعال + تحویل گیت‌هاب
├── /resources                 کارت‌های ۹ هفته + دانلود
│   └── /resources/week/<n>    فایل‌های یک هفته
├── /gamification/leaderboard  رتبه‌بندی کلاس
├── /dashboard/certificate  ★  مسیر مدرک (نمای کامل پیشرفت) [جدید]
├── /login · /logout           احراز هویت
└── /admin                     پنل ادمین (موجود، با نقش is_admin)
```

★ = صفحه‌ی جدید برای هدف G4 (هل دادن به مدرک).

## ۴. مشخصات بخش‌ها (Feature Specs)

هر بخش: هدف، عناصر کلیدی، وضعیت فعلی، تغییرات لازم، معیار پذیرش.

### ۴.۱ داشبورد اصلی `/` (هسته‌ی پروژه)

**هدف:** دانش‌آموز با یک نگاه بداند «کجاست، چقدر تا مدرک فاصله دارد، الان چه کار کند».

**عناصر:**
1. **بنر پیشرفت مدرک** (بالا، برجسته): نوار پیشرفت درصدی + متن «۷ از ۹ هفته» + CTA.
2. **۴ کارت آمار** (grid): XP کل · استریک روزانه · تکالیف فعال · رتبه‌ی شما.
3. **تکالیف نزدیک‌به‌مهلت** (لیست ۳تایی): عنوان + countdown + دکمه‌ی تحویل.
4. **هفته‌ی جاری / بعدی** (کارت): لینک به پایگاه دانش.
5. **میان‌برهای ابزار مطالعه** (گرید آیکونی): فلش‌کارت، چالش زمان‌دار، تحلیل ضعف، تایمر.
6. **آخرین فعالیت‌ها** (timeline کوتاه): آخرین XP‌ها/کوییزها.

**وضعیت فعلی:** فقط `"Hi sina"` (placeholder).
**تغییرات:** بازنویسی کامل + مدل‌ها/سرویس جدید.

**معیار پذیرش:**
- [ ] دانش‌آموز لاگین‌شده در < ۳ ثانیه می‌فهمد چند درصد تا مدرک فاصله دارد.
- [ ] ۴ کارت آمار داده واقعی از DB نشان می‌دهند.
- [ ] لیست تکالیف نزدیک‌به‌مهلت از کوئری DB می‌آید.

---

### ۴.۲ پایگاه دانش هفته `/kb/week/<n>` (مرور + کوییز)

**هدف:** مرور تقلب‌نامه‌ی هر هفته + کوییز تعاملی + ابزار مطالعه همان هفته.

**عناصر:**
1. **هدر هفته**: شماره + عنوان + وضعیت تکمیل + دکمه‌ی «من خواندم» (موجود، +۵ XP).
2. **تب‌ها**: مفاهیم (cheat-sheet) · کد · کوییز · یادداشت.
3. **کوییز تعاملی** (HTMX): بدون رفرش کامل، نتیجه در DB ثبت می‌شود.
4. **بخش ابزار مطالعه**: فلش‌کارت‌های همان هفته + چالش زمان‌دار.

**وضعیت فعلی:** صفحه‌ی ساده با دکمه‌ی «من خواندم». داده‌ی مفاهیم/کوییز وجود ندارد.
**تغییرات:** اضافه‌کردن مدل داده (مفاهیم/سؤال‌ها) + کوییز HTMX + تب‌بندی.

**معیار پذیرش:**
- [ ] کوییز نمره را در DB ثبت می‌کند (نه فقط localStorage).
- [ ] دکمه‌ی «من خواندم» +۵ XP می‌دهد (موجود، حفظ شود).

---

### ۴.۳ تکالیف + گیت‌هاب `/assignments` (بهبود UX)

**هدف:** «الان چه تکالیفی داری؟» با تجربه‌ی مدرک‌محور.

**عناصر:**
1. **کارت تکلیف** مدرک‌محور: عنوان + هفته + مهلت (countdown) + وضعیت (تحویل‌داده/نه).
2. **فرم تحویل**: لینک گیت‌هاب + اعتبارسنجی + دکمه‌ی «تحویل (+۲۰ XP)».
3. **وضعیت تصحیح**: نمایش grade/feedback از submissions موجود.

**وضعیت فعلی:** پیاده‌سازی شده اما پایه‌ای (لیست ساده، بدون countdown، بدون وضعیت).
**تغییرات:** بهبود بصری + countdown + نمایش وضعیت تحویل کاربر.

**معیار پذیرش:**
- [ ] countdown مهلت به‌صورت زنده یا محاسبه‌شده نمایش داده می‌شود.
- [ ] تکلیفی که کاربر تحویل داده، با نشان «تحویل‌شده» متمایز می‌شود.

### ۴.۴ رتبه‌بندی + XP + استریک `/gamification/leaderboard` (تم هاروارد)

**هدف:** انگیزه‌ی رقابتی + نمایش رتبه‌ی شخصی.

**عناصر:**
1. **جدول رتبه‌بندی**: ۱۰ نفر برتر با مدال + رتبه‌ی شما برجسته (Crimson).
2. **کارت جمع‌بندی شما**: XP + استریک + رتبه‌ی شما.
3. **سیستم استریک**: محاسبه‌ی روزانه (مبتنی بر آخرین فعالیت).

**وضعیت فعلی:** جدول ساده آبی، بدون استریک واقعی، بدون رتبه‌ی شخصی برجسته.
**تغییرات:** بازطراحی Crimson + محاسبه‌ی استریک + رتبه‌ی شما.

**معیار پذیرش:**
- [ ] جدول تم Crimson دارد و رتبه‌ی کاربر فعلی هایلایت می‌شود.
- [ ] استریک بر اساس فعالیت واقعی محاسبه می‌شود.

**هدف:** دسترسی سریع به اسلاید/جزوه/سورس هر هفته.

**عناصر:**
1. **کارت‌های ۹ هفته** هارواردی با تعداد فایل.
2. **فیلتر/جستجو** (اختیاری فاز بعدی).

**وضعیت فعلی:** کارت‌های پایه‌ای آبی.
**تغییرات:** بازطراحی Crimson.

**معیار پذیرش:**
- [ ] کارت‌ها تم هاروارد دارند و دانلود کار می‌کند (موجود).

### ۴.۶ مسیر مدرک `/dashboard/certificate` ★ (جدید — هدف G4)

**هدف:** نمایش بصری کامل مسیر CS50 تا مدرک، بزرگ‌ترین محرک انگیزه.

**عناصر:**
1. **نوار پیشرفت کلی**: درصد تکمیل ۹ هفته.
2. **چک‌لیست الزامات مدرک**: تکمیل هفته‌ها + کوییز‌ها + تکالیف نهایی.
3. **بمب زمانی تخمینی**: «با این ритm، ~X هفته تا مدرک».
4. **دستاوردها/نشان‌ها**: باز شده/قفل‌شده.

**وضعیت فعلی:** وجود ندارد.
**تغییرات:** صفحه + سرویس جدید.

**معیار پذیرش:**
- [ ] دانش‌آموز می‌فهمد دقیقاً چه چیزهایی برای مدرک کم دارد.

### ۴.۷ ابزارهای مطالعه (منتقل‌شده از Next.js، ساده‌شده)

**هدف:** بهترین قابلیت‌های ابزار مرور، اما در بافت درست (داخل صفحات، نه navbar).

| ابزار | محل قرارگیری | وضعیت در Next.js | حالت جدید |
|-------|--------------|------------------|-----------|

| دستاوردها | مسیر مدرک | localStorage | DB |
| استریک | داشبورد + رتبه‌بندی | localStorage | DB |

**معیار پذیرش:**
- [ ] فلش‌کارت‌ها برای هر کاربر در DB ذخیره و بازیابی می‌شوند.
- [ ] تحلیل ضعف بر اساس داده‌ی واقعی کوییز کار می‌کند.

## ۵. مدل داده‌ای (تغییرات)

مدل‌های موجود: `User, Assignment, Submission, XPLog, Resource`.

### مدل‌های جدید (طراحی PostgreSQL-safe)

```python
# پیشرفت هر هفته برای هر کاربر (تکمیل کوییز، مطالعه، و...)
class WeekProgress(db.Model):
    id            # PK
    user_id       # FK → User
    week          # 0..8
    cheat_sheet_read  # bool (دکمه‌ی «من خواندم»)
    best_quiz_score    # int (بهترین نمره‌ی کوییز این هفته)
    completed     # bool (محاسبه‌شده)
    last_active   # datetime
    __table_args__ = (UniqueConstraint("user_id", "week"),)

# ثبت هر تلاش کوییز (برای تحلیل ضعف)
class QuizAttempt(db.Model):
    id            # PK
    user_id       # FK → User
    week          # 0..8
    score         # int
    total         # int
    answers_json  # Text (کدام سؤال‌ها غلط — برای تحلیل ضعف)
    created_at    # datetime

# دستاوردهای بازشده
class Achievement(db.Model):
    id            # PK
    user_id       # FK → User
    key           # str (مثلاً "perfect", "streak_7")
    unlocked_at   # datetime
    __table_args__ = (UniqueConstraint("user_id", "key"),)

# فلش‌کارت‌های شخصی یا سیستم
class Flashcard(db.Model):
    id            # PK
    user_id       # FK → User (NULL = سیستم، همه)
    week          # 0..8
    front         # Text
    back          # Text
    box           # int (الگوریتم Leitner برای تکرار فاصله‌دار)
    last_reviewed # datetime
```

**نکته:** داده‌ی محتوای هفته‌ها (مفاهیم، کد، سؤال‌های کوییز) فعلاً به‌صورت **داده‌ی seed در
`init_db.py`** یا ماژول پایتون قرار می‌گیرد (مشتق از `src/data/weeks-data.ts` فعلی)، تا
سادگی حفظ شود و نیازی به migration سنگین نباشد.
