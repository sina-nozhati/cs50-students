## Final Project

<https://cs50.harvard.edu/x/project/> — submit with `submit50 cs50/problems/2026/x/project` by 2027-06-30T23:59:00+00:00.

- Any software project of your choice that draws on the course; any language(s), CS50 Codespace optional.
- Solo, or a group of 2-3 with proportionally larger scope (2x / 3x); a solo project should take more effort than any problem set.
- AI tools other than CS50's own are allowed for the final project only, but the essence must be your own and any use must be cited in code comments.
- Step 1: a video of at most 3 minutes, opening with project title, your name, GitHub and edX usernames, city and country, and recording date; uploaded to YouTube (or similar), unlisted is OK but not private; then submit the linked form.
- Step 2: a README.md (exact name) with title, video URL and a detailed description of the project, each file and design choices; around 750 words suggested ('several hundred' minimum); submit with submit50 from the project folder (zip if too large; must be under 100MB).
- Step 3: open the Gradebook (cs50.me/cs50x) after submitting; this triggers the free CS50 Certificate and, within 30 days, the edX verified certificate if purchased.
- Submissions are audited for academic honesty; violations lead to removal and certificate revocation.

## Certificate & rules

Free CS50 Certificate if you score at least 70% on each problem set's required problems and the final project; edX verified certificate available separately (paid) via cs50.edx.org. Claim it from the Gradebook before the deadline.

- No final exam; only the assignments listed each week (FAQ).
- Less/more comfortable: choose either; no extra credit for 'more'; if both are submitted, the higher score counts (FAQ).
- You may resubmit a problem; the most recent submission counts (FAQ).
- 70% of problems is not enough: every required assignment needs >= 70% (FAQ).
- No per-assignment deadlines; overall course deadline 2027-06-30 23:59 UTC; current term began 2026-01-01; may be extended by 6 or 12 months (FAQ).
- Work from 2025 carries over to the Gradebook; work last submitted before 2025 does not (FAQ).
- If extended, completed work (>=70% before deadline) from the current term carries forward; for weeks with multiple problems all must be complete (FAQ).
- Free certificate link appears in the Gradebook about 4 hours after the last required score (FAQ).

## Problem summaries

### Starting from Scratch — PSet 0

<https://cs50.harvard.edu/x/psets/0/scratch/>

Build any Scratch project you like (story, game, animation, etc.) at scratch.mit.edu. It must use at least two sprites (at least one not a cat), at least three scripts, and at least one conditional, one loop and one variable. It must also include a custom block you made yourself that takes at least one input. It should be more complex than most lecture demos, and is submitted by uploading the .sb3 file at submit.cs50.io.

Concepts: Scratch, sprites, events, conditionals, loops, variables, custom blocks / abstraction

### Hello, World — PSet 1

<https://cs50.harvard.edu/x/psets/1/world/>

Write the classic first C program, hello.c in a folder called world, that prints "hello, world" followed by a newline. The page gives the exact code and suggests typing it by hand to build muscle memory. It is mainly a check that the codespace, make and check50 work. The pset page says to 'Complete' it, and its page says it need not be submitted.

Concepts: C syntax, printf, compiling with make, codespace setup

### Hello, It’s Me — PSet 1

<https://cs50.harvard.edu/x/psets/1/me/>

Write hello.c in a folder called me that asks the user for their name and greets them, e.g. printing "hello, Adele". It introduces getting a string from the user with the CS50 library and formatting it into output with printf.

Concepts: get_string, printf format codes, variables, cs50.h

### Mario (less comfortable) — PSet 1

<https://cs50.harvard.edu/x/psets/1/mario/less/>

Write mario.c (folder mario-less) that prints a right-aligned half-pyramid of # bricks, like the staircase at the end of Super Mario Bros. World 1-1. The program asks for the height as an int and keeps re-prompting until it gets a positive integer. The page walks through pseudocode, a do-while loop for input and nested loops for printing rows.

Concepts: do-while loops, nested for loops, input validation, pseudocode, functions

### Mario (more comfortable) — PSet 1

<https://cs50.harvard.edu/x/psets/1/mario/more/>

The harder Mario variant: mario.c (folder mario-more) prints two adjacent right- and left-aligned pyramids separated by a gap two hashes wide, as at the start of World 1-1. The user is prompted for a height from 1 to 8 inclusive and re-prompted until they comply. Output should match the examples shown on the page.

Concepts: nested loops, input validation, string output formatting

### Cash (less comfortable) — PSet 1

<https://cs50.harvard.edu/x/psets/1/cash/>

Write cash.c that prints the minimum number of coins (quarters, dimes, nickels, pennies) needed for a given amount of change in cents. The user is re-prompted until they enter a non-negative int. It illustrates a greedy algorithm, which always takes the largest coin that still fits.

Concepts: greedy algorithms, arithmetic / modulo, functions, input validation

### Credit (more comfortable) — PSet 1

<https://cs50.harvard.edu/x/psets/1/credit/>

Write credit.c that reads a card number and reports whether it is a valid American Express, MasterCard or Visa number, or invalid. Validity is checked with Luhn's checksum algorithm, plus each company's length and starting-digit rules. Numbers are read as a long, so the program must extract digits arithmetically.

Concepts: Luhn's algorithm, long integers, digit extraction with % and /, conditionals

### Scrabble — PSet 2

<https://cs50.harvard.edu/x/psets/2/scrabble/>

Write scrabble.c that asks two players for a word each and scores them with Scrabble letter values, ignoring case and non-letters. It prints "Player 1 wins!", "Player 2 wins!" or "Tie!". The page suggests storing the point values in an array and writing a compute_score function.

Concepts: arrays, strings as char arrays, ASCII arithmetic, ctype.h, functions

### Readability — PSet 2

<https://cs50.harvard.edu/x/psets/2/readability/>

Write readability.c that asks for some text and estimates the US grade level needed to read it with the Coleman-Liau index (based on average letters and sentences per 100 words). It prints "Grade X" rounded to the nearest integer, "Grade 16+" for 16 or higher, or "Before Grade 1" below 1. Letters, words and sentences are counted by simple rules described on the page.

Concepts: string iteration, counting characters, type casting / floats, math.h round, functions

### Caesar (less comfortable) — PSet 2

<https://cs50.harvard.edu/x/psets/2/caesar/>

Write caesar.c that encrypts text with a Caesar cipher, shifting each letter by a key given as a single command-line argument. The key must be a non-negative integer, otherwise the program prints a usage message and returns 1. The text is read from the user, case is preserved, non-letters are left unchanged, and the output is labelled ciphertext.

Concepts: command-line arguments (argc/argv), cryptography, modular arithmetic, ctype.h, input validation

### Substitution (more comfortable) — PSet 2

<https://cs50.harvard.edu/x/psets/2/substitution/>

Write substitution.c that encrypts text with a substitution cipher, where a 26-letter key given on the command line maps each letter of the alphabet to another. The key must be validated (exactly 26 alphabetic characters, each letter once) or the program exits with an error. Case must be preserved and non-letters left unchanged.

Concepts: command-line arguments, cryptography, arrays, input validation, ctype.h

### Sort — PSet 3

<https://cs50.harvard.edu/x/psets/3/sort/>

Analyse three compiled sorting programs (sort1, sort2, sort3) and work out which uses selection sort, bubble sort or merge sort. Run them on the provided sorted, reversed and random number files and compare their running times. Record each answer, with an explanation, in answers.txt.

Concepts: sorting algorithms, running time / Big O, best vs worst case, empirical timing

### Plurality — PSet 3

<https://cs50.harvard.edu/x/psets/3/plurality/>

Complete the distribution code in plurality.c for a first-past-the-post election. You implement vote, which records a ballot for a named candidate (returning false for an invalid name), and print_winner, which prints the candidate(s) with the most votes, including ties. Candidates are given as command-line arguments.

Concepts: structs, arrays, linear search, strcmp, functions

### Runoff (more or less comfortable) — PSet 3

<https://cs50.harvard.edu/x/psets/3/runoff/>

Complete runoff.c, a ranked-choice (instant runoff) election. Voters rank candidates, and the program repeatedly tabulates first-choice votes among remaining candidates, checks for a majority winner, finds the minimum vote count, detects all-way ties and eliminates last-place candidates. You implement vote, tabulate, print_winner, find_min, is_tie and eliminate.

Concepts: 2D arrays, structs, ranked-choice voting, algorithm design

### Tideman (very, very, very comfortable) — PSet 3

<https://cs50.harvard.edu/x/psets/3/tideman/>
